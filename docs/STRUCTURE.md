# โครงสร้างโปรเจกต์ ZENTRA

เอกสารนี้อธิบายว่าไฟล์แต่ละส่วนทำหน้าที่อะไร และใครเรียกใคร
ปรับปรุงล่าสุด: 2026-08-16

---

## ภาพรวม 4 ชั้น

```
ผู้ใช้ → ui/ (หน้าจอ) → server/ (API) → pipeline/ (จัดคิวกล้อง) → backend/ (AI)
```

แต่ละชั้นรู้จักเฉพาะชั้นที่อยู่ล่างกว่าเท่านั้น — `backend/` ไม่รู้จัก `server/` เลย
จึงเอาไปรันแยกบนเครื่องอื่น (เช่น `cloud/`) ได้โดยไม่ต้องแก้

---

## สิ่งที่ผู้ใช้ดับเบิลคลิก (โฟลเดอร์หลัก)

| ไฟล์ | หน้าที่ |
|---|---|
| `ZENTRA.bat` | **ไฟล์เดียวที่ผู้ใช้ต้องกด** — ครั้งแรกติดตั้งให้เองแล้วเปิดต่อ ครั้งต่อไปเปิดทันที |
| `INSTALL.bat` | ตัวติดตั้งจริง `ZENTRA.bat` เรียกให้อัตโนมัติ (`/auto` = ไม่ pause ตอนจบ) เก็บไว้สำหรับซ่อมระบบ |
| `README.txt` | เริ่มต้นใช้งาน 3 ขั้นตอน |
| `MANUAL_TH.html` | คู่มือฉบับเต็มภาษาไทย เปิดในเบราว์เซอร์ |

### ตัวติดตั้งออกแบบให้ "โหลดจาก GitHub แล้วรันได้เลย"

`setup/*.exe` ไม่ขึ้น git (ใหญ่เกิน) ตัวติดตั้งจึงต้องหาเองเมื่อไม่พบไฟล์:

| ขั้น | ทำอะไร | ถ้าไม่มีของในเครื่อง |
|---|---|---|
| [0/7] | ทดลอง**สร้างไฟล์ที่ลึกเท่า torch จริง** (145 ตัวอักษร) | บอกให้ย้ายโฟลเดอร์ พร้อมบอกพาธปัจจุบัน |
| [1/7] | หา Python 3.11 | โหลดจาก python.org (~25 MB) แล้วลงแบบเงียบ per-user |
| [3/7] | หา WebView2 | โหลด evergreen bootstrapper จาก Microsoft (~2 MB) |

> ขั้น [0/7] ใช้การ**ทดลองเขียนไฟล์จริง** ไม่ใช่การนับตัวอักษร เพราะเครื่องที่เปิด
> `LongPathsEnabled` ไว้จะรับพาธยาวได้ การนับตัวอักษรจะห้ามผิดโดยไม่จำเป็น

> `.gitattributes` บังคับ `*.bat` เป็น CRLF และ `*.sh` เป็น LF เสมอ
> ทั้งทาง `git clone` และปุ่ม Download ZIP ของ GitHub

## `ui/` — หน้าจอ (HTML/CSS/JS ล้วน ไม่มี framework)

```
ui/
├── index.html              เปลือกหน้าเดียว โหลด app.js
├── assets/
│   ├── app.js              เราเตอร์ + แถบเมนู + ไอคอน SVG + ตัวช่วยที่ใช้ร่วมกัน
│   ├── style.css           design token 3 ชั้น + สไตล์ทุกหน้า
│   ├── logo-mark.png       เหยี่ยว (กระเบื้องแบรนด์ในแถบเมนู)
│   ├── logo-wordmark.png   โลโก้เต็มพร้อมชื่อ (splash / source / settings)
│   ├── logo-boot.png       โลโก้สำหรับหน้าต่างเริ่มระบบใน app.py (ฝังเป็น data URI)
│   ├── zentra.ico          ไอคอน taskbar + console (7 ขนาด)
│   ├── fonts/plex-thai/    IBM Plex Sans Thai 12 ไฟล์ — โฮสต์ในเครื่อง ไม่ต่อ CDN
│   └── vendor/             chart.umd.min.js (กราฟหน้าแดชบอร์ด)
└── screens/                7 หน้า โหลดแบบ dynamic ด้วย fetch()
    ├── splash.html         หน้าเริ่มระบบ
    ├── source.html         เลือกแหล่งภาพ (webcam / RTSP / ไฟล์วิดีโอ)
    ├── dashboard.html      ภาพสด + KPI + กราฟ + รายการแจ้งเตือน
    ├── cameras.html        จัดการกล้อง + กำหนดบทบาท (PPE / โซน / การล้ม)
    ├── history.html        ประวัติเหตุการณ์ + ส่งออก CSV/PDF
    ├── settings.html       ตั้งค่าทั้งระบบ + LINE + ชุดข้อมูลฝึกโมเดล

```

**กติกา:** ทุกหน้าต้องมีฟังก์ชัน `init_<ชื่อหน้า>()` — `app.js` เรียกให้หลังแทรก HTML เสร็จ

## `server/` — เว็บ API (FastAPI)

| ไฟล์ | หน้าที่ |
|---|---|
| `api.py` | ทุก endpoint `/api/*` + WebSocket ภาพสด + เสิร์ฟไฟล์ `ui/` |
| `store.py` | ฐานข้อมูลเหตุการณ์ SQLite + ภาพหลักฐาน (`data/zentra.db`) |
| `report.py` | สร้างรายงาน PDF ภาษาไทย → `data/reports/` |
| `jobs.py` | งานเบื้องหลัง: ฝึกโมเดล / อัปโหลดชุดข้อมูล |
| `power.py` | เตือนเมื่อ Windows ตั้งแผนพลังงานไม่เหมาะกับงาน AI |

## `pipeline/` — ตัวจัดการกล้องหลายตัว

| ไฟล์ | หน้าที่ |
|---|---|
| `manager.py` | ทะเบียนกล้อง, สตาร์ท/หยุด, กันเลือกอุปกรณ์ซ้ำ, แชร์โมเดลชุดเดียว |
| `pipeline.py` | ลูปต่อกล้อง 1 ตัว: อ่านเฟรม → ตรวจจับ → แจ้งเตือน → บันทึก |
| `scheduler.py` | เธรดเดียวรันโมเดลให้ทุกกล้อง — รวมเฟรมยิงทีเดียวแบบ batch แล้วแยกผลคืนแต่ละกล้อง |
| `frame_broadcaster.py` | ส่งเฟรมที่วาดผลแล้วออกทาง WebSocket |

## `backend/` — สมอง AI (แยกอิสระ ไม่รู้จัก server/)

```
backend/
├── config.py               ค่าตั้งทั้งหมด อ่านจาก .env — จุดเดียวที่ควรแก้ค่า
├── .env                    ค่าจริงของเครื่องนี้ (ไม่ขึ้น git — มีโทเคน LINE)
├── .env.example            แม่แบบสำหรับเครื่องใหม่
├── alerts/line_notify.py   ส่งข้อความ + รูปเข้า LINE OA
├── assets/
│   ├── models/             fall_detection_transformer.tflite (ตัวจำแนกการล้ม)
│   ├── fonts/              Sarabun-SemiBold.ttf (วาดข้อความไทยลงภาพ + PDF)
│   └── trackers/           bytetrack_zentra.yaml (ค่าติดตามที่จูนแล้ว)
├── models/                 ptt โมเดล YOLO — ไฟล์ใหญ่ ~84 MB
│   ├── ppe_finetuned.pt    ตรวจ PPE (เทรนเองจาก yolo11m)
│   ├── yolo11m.pt          ตรวจคน
│   └── yolo11n-pose.pt     ตรวจท่าทาง (ใช้ตรวจการล้ม)
├── data/collected/         เฟรมที่ระบบเก็บอัตโนมัติไว้เทรนรอบถัดไป (ไม่ขึ้น git — PDPA)
└── utils/
    ├── ppe_engine.py       ตัวหลัก — รวมทุกโมดูลตรวจจับเข้าด้วยกัน
    ├── detect_track.py     ห่อ ultralytics (โหลดโมเดล + ติดตามวัตถุ)
    ├── tracker.py          ByteTrack ที่แก้ให้กู้ track ที่หลุดกลับมาได้
    ├── ppe_association.py  จับคู่อุปกรณ์ที่เจอเข้ากับคนที่ใส่
    ├── pose_visibility.py  ดูจากท่าทางว่าอุปกรณ์ชิ้นไหนมองเห็นพอจะตัดสินได้ (กันเตือนตอนหันหลัง)
    ├── fall_detector.py    ลำดับเวลา 30 เฟรม → TFLite → ความน่าจะเป็นการล้ม
    ├── temporal.py         กรองสัญญาณรบกวนตามเวลา (กันเตือนผิด)
    ├── zone_geometry.py    โหลด/ย่อขยายรูปหลายเหลี่ยม + ทดสอบจุดอยู่ในพื้นที่
    ├── collector.py        เก็บเฟรมอัตโนมัติเข้า data/collected/
    └── model_hub.py        โหลดโมเดลครั้งเดียวแล้วแชร์ทุกกล้อง
```

## `data/` — ข้อมูลของเครื่องนี้ (ส่วนใหญ่ไม่ขึ้น git)

| ไฟล์ | ขึ้น git? | หมายเหตุ |
|---|---|---|
| `settings.json` | ไม่ | มีโทเคน LINE + รหัสกล้อง RTSP |
| `settings.example.json` | ใช่ | แม่แบบ |
| `settings.backup-*.json` | ไม่ | จุดย้อนกลับถ้า settings.json พัง |
| `zones.json` | ใช่ | รูปหลายเหลี่ยมพื้นที่อันตราย (พิกัด 0–1) |
| `zentra.db` | ไม่ | เหตุการณ์ทั้งหมด — PDPA |
| `snapshots/` | ไม่ | ภาพหลักฐาน — PDPA |
| `reports/` | ไม่ | PDF ที่สร้างแล้ว |

## `cloud/` — ตัวเลือกประมวลผลบนเซิร์ฟเวอร์ (ยังไม่เปิดใช้)

เมนูในแอปถูกถอดออกแล้ว แต่เก็บโค้ดไว้เผื่ออนาคต
`inference_server.py` เอา `backend/utils/ppe_engine.py` ไปห่อเป็น API — ตรรกะตรวจจับเหมือนกันทุกบรรทัด

## `setup/` — ตัวติดตั้งออฟไลน์

`python-3.11.9-amd64.exe` + `MicrosoftEdgeWebview2Setup.exe`
ไม่ขึ้น git (`setup/*.exe`) เพราะใหญ่และโหลดจากต้นทางได้
